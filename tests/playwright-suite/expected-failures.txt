# Playwright tests expected to fail on zebkit's endpoint:
#   <project/file glob> | <title regex or *> | REASON
# The first entry that matches a failure explains it, so an entry names the tests
# that have its cause: * only when a whole file is about what the entry says. A
# test that timed out or crashed is never explained here: summarize.py counts those
# apart. It also lists entries that matched nothing, which is how a fix is noticed.

# What a content-layer engine does not have (Chrome's WebUI and extensions), or
# Playwright's own server, which a connected client does not have. Tests that
# launch a browser get zebkit-run (scripts/playwright-suite.sh).
library/chromium/extensions.spec.ts | * | Chrome's extensions (a persistent context with --load-extension), which a content-layer engine does not have
library/inspector/*.spec.ts | * | the recorder driven through the endpoint (BrowserContext.startRecording, page.pickLocator, the inspector's own page) is Playwright's server's; the CLI's codegen, which launches zebkit-run, runs
library/debugger.spec.ts | * | page.pause() and the Debugger object need Playwright's own server (docs/AUTOMATION.md, section 5)

# Not implemented by the endpoint.
library/chromium/chromium.spec.ts | WebUI navigation | the error's text for a refused WebUI page differs: a content-layer engine has no WebUI

# Differ, each with its cause known; a file's entry says what its failures are.
