# zebkit 0.4.0

System integration: everything a page or the engine would show the person,
or ask of the system, now has a default that works and a function of the
application's that replaces it, in C, Rust, Python and host JavaScript. The
window's frame, menus, dialogs, choosers, capture, notifications, the tray,
the Dock and the taskbar, sharing, the system's theme, power and displays.
`docs/SYSTEM_INTEGRATION.md` is the design; its section 5 has every surface
with its default and status on each system, and `src/engine/surfaces.json`
is the registry `scripts/check-surfaces.py` checks against the code.

The Rust crates `zebkit`, `zebkit-rs` and `zebkit-build` 0.4.0 download these
archives, each checked against its SHA-256 in `bindings/rust/zebkit-rs/engines.txt`.
The Python binding `zebkit` 0.4.0 is the binding alone; its engine is this
release's archive.

## What changed since 0.3.0

**What reached the system without the application, decided.** File System
Access (`showOpenFilePicker()` and the others) goes through the file chooser
hook (`patches/1084`), and reading or writing beyond what was picked is the
`file-system-read` or `file-system-write` permission, denied without a hook.
`registerProtocolHandler()` is the `protocol-handler` permission and no longer
reports a registration it did not make. Pointer and keyboard lock are
permissions.

**Windows made with options.** `zebkit_view_new_with_options()`: the frame
(`system`, `overlay` as Window Controls Overlay, `none`), its colours and
height, a hidden start, position, limits, background, appearance; state,
actions and events; drag regions from the page's CSS `app-region` for granted
origins, or the host's rectangles; options for popups. `examples/custom-titlebar`
is a page as the title bar.

**The system's appearance.** With the startup setting `appearance.follow`,
pages follow the system's dark mode, contrast and forced colours live (on
Linux the XDG portal); `zebkit_get_environment()` and its change event. The
accessibility trees are built when an assistive technology asks.

**Menus and dialogs.** Menu items with state by id (enabled, checked, radio
groups), changed in place. The default context menu where there is a window,
and the application's: replaced, extended, or its commands run against what
was right-clicked. JavaScript dialogs and HTTP sign-in with Chromium's views
dialogs on Linux and Windows where there is a window; a client certificate
list. `EyeDropper.open()` answered by the application.

**Notifications and the desktop.** Web notifications, undecided until the
application permits them, then shown by the application or by the system:
`org.freedesktop.Notifications` on Linux, UserNotifications on macOS, a
notification area balloon on Windows; clicks and closes reach the page and its
service worker. A tray icon with a menu (a StatusNotifierItem on Linux). The
Dock's and the taskbar's badge, progress and request for attention, and the
Dock's menu. `navigator.share()` through the application. Opening a URL or
showing a file with the system's handler, never through a shell.

**Capture, devices, power.** `getDisplayMedia()` through the media access
hook: the view itself, with its sound, or the whole screen. WebUSB, WebHID and
Web Serial choosers as one hook, `zebkit_view_on_device_chooser`, the device
list following the system's devices; `patches/1085` keeps serial ports from
crashing a build without a platform Bluetooth. Suspend, resume, the power
source and the session's lock and unlock as events; the screens and their
changes; keeping the system awake.

**Defaults that changed.** `Notification.permission` is `"default"` until the
application decides, where 0.3.0 said `"denied"`; requests are still denied
without a decision. Everything else keeps 0.3.0's behaviour unless the
application asks for the new one.

Not in this release, with the reasons in `docs/SYSTEM_INTEGRATION.md`: a
system screen-capture picker as the default (the application chooses the
source), Web Bluetooth, physical printing (decided against for size; PDF
output stays), and tests that read the platform accessibility trees.
