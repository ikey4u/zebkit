# zebkit 0.2.1

Native screenshots more than twice as fast, and their pixels without encoding;
the command-line tools in every archive; the same vendor libraries on every
system; `zebkit.ui` styled as its classes say; and the commands that publish
the Rust crates and the Python binding.

| Archive | System | Unpacked | `.tar.xz` |
|---|---|---:|---:|
| `zebkit-0.2.1-x86_64-unknown-linux-gnu.tar.xz` | Linux x86-64, glibc 2.17 or newer | 180.8 MiB | 61.3 MiB |
| `zebkit-0.2.1-aarch64-apple-darwin.tar.xz` | macOS, Apple silicon | 158.5 MiB | 48.0 MiB |
| `zebkit-0.2.1-x86_64-pc-windows-msvc.tar.xz` | Windows 10 or newer, x64 | 245.8 MiB | 73.4 MiB |

The Rust crates `zebkit`, `zebkit-rs` and `zebkit-build` 0.2.1 download these
archives, each checked against its SHA-256 in `bindings/rust/zebkit-rs/engines.txt`.
The Python binding `zebkit` 0.2.1 is the binding alone; its engine is this
release's archive.

## What changed since 0.2.0

**Screenshots** (Linux, `scripts/automation-bench.sh`, the bench page at 1280 by
800, medians):

| | 0.2.0 | 0.2.1 | Chrome 156 over CDP |
|---|---:|---:|---:|
| Native `page.screenshot()`, PNG | 31.5 ms | 12.4 ms | 33.8 ms |
| Native JPEG | | 13.9 ms | 32.9 ms |
| Native pixels, unencoded | | 9.3 ms | |
| Native click | 4.9 ms | 2.0 ms | |

- The PNG is encoded as Chromium encodes screencasts (deflate level 1, the Up
  filter): 15.9 to 4.2 ms, the same pixels, the file about half as large again.
  JPEG and WebP keep their encoders.
- The capture's shared memory is made in one call (`MADV_POPULATE_WRITE`)
  instead of a page fault a page, 4.5 to 1.8 ms; the sandbox allows that call in
  the GPU process's policy only (`patches/1082`).
- `zebkit_automation_screenshot_pixels()` takes Playwright's screenshot options
  and answers with RGBA pixels, width, height and stride (`patches/1081`); in
  Python `screenshot_pixels()`, in Rust `screenshot_pixels()`. Playwright's own
  API is unchanged; over CDP zebkit stays as Chrome is.

**Tools in the archives.** `zebkit-run`, `zebkit-js` and `zebkit-mcp` come with
the engine on every system, sandboxed on Windows; `zebkit-mcp` serves MCP over
standard input and output on Windows too.

**Vendor libraries.** FreeType's BDF and synthesis are built on every system
(`patches/1080`), and the list of exported functions is made again when the
objects change: about 7,490 functions on Linux, macOS and Windows alike.

**`zebkit.ui`.** Buttons take their background, border, corner radius and
padding from their classes, labels keep their color, fields their background and
border; `examples/ui/todo.mjs` is a day planner that shows it.

**Publishing.** `mise run r:crate` publishes the Rust crates to crates.io and
`mise run r:python` the Python binding to PyPI, their tokens from the
environment (`CARGO_REGISTRY_TOKEN`, `UV_PUBLISH_TOKEN` or `PYPI_TOKEN`).

**Examples.** `examples/gpui-browser`, a tabbed browser in GPUI-KIT around
zebkit's pages.

suite.

## Missing and known issues

As in 0.2.0 (`docs/releases/0.2.0.md`), and:

- The GPU process's `MADV_POPULATE_WRITE` allowance has not run under a real
  seccomp filter: the build machine cannot run Linux's sandbox, and macOS and
  Windows have no seccomp.
- `examples/gpui-browser` has not been built on macOS.
