# zebkit 0.3.0

Chromium 157, and with it HTML in canvas: a page draws its own elements into a
2D canvas, turned, scaled or reflected, and they stay elements, typed into and
clicked where they are drawn. Pages are in the system's locale again on every
system.

| Archive | System | Unpacked | `.tar.xz` |
|---|---|---:|---:|
| `zebkit-0.3.0-x86_64-unknown-linux-gnu.tar.xz` | Linux x86-64, glibc 2.17 or newer | 183.7 MiB | 62.3 MiB |
| `zebkit-0.3.0-aarch64-apple-darwin.tar.xz` | macOS, Apple silicon | 153.1 MiB | 41.8 MiB |
| `zebkit-0.3.0-x86_64-pc-windows-msvc.tar.xz` | Windows 10 or newer, x64 | 252.2 MiB | 75.6 MiB |

The Rust crates `zebkit`, `zebkit-rs` and `zebkit-build` 0.3.0 download these
archives, each checked against its SHA-256 in `bindings/rust/zebkit-rs/engines.txt`.
The Python binding `zebkit` 0.3.0 is the binding alone; its engine is this
release's archive.

## What changed since 0.2.1

**Chromium 157.0.8103.38** (from 155.0.8059.84). The 61 patches of
`patches/series` carried forward, sixteen of them written again where 157
changed the code they touch, and one new (1083, below). The user agent is Chrome 157's.

**HTML in canvas** ([the proposal](https://github.com/WICG/html-in-canvas),
on in Chrome 157): `<canvas content=drawable>` with `drawable` children,
`drawElementImage()` in the canvas's `paint` event, `requestPaint()`.
`tests/engine/html_in_canvas.py` checks that a drawn button is in the view's
pixels where it is drawn, that hit testing, the view's own mouse and
Playwright's `click()` reach it there, and that it moves with its drawing.
`examples/html-in-canvas.html` is a form drawn turned, with its reflection,
that still types and submits:

    ./window file://$PWD/examples/html-in-canvas.html

**The system's locale.** Chromium 157 starts its default locale at en-US
until the embedder sets one, as Chrome does from its language packs; on 157
pages would have been in English everywhere. `patches/1083` starts it at the
system's, en-US without one, which also replaces the Windows-only workaround
of 0.2.x. `tests/engine/system_locale.py` checks a Japanese and a C locale.

**Fullscreen needs focus.** As in Chrome 157, only a focused view may go
fullscreen. `View.focus()` is in Python and `zebkit-js` too, as it was in C
and Rust.

**Popups at their view's scale.** Under `--headless`, a `<select>` list or
another popup took the first display's scale instead of its view's, and was
drawn in a corner at scale 2; it takes its view's now.

**macOS.** From macOS 26, Chromium hides a window another one covers, as
Chrome does; `docs/MACOS.md` says how a test that needs covered windows
drawn turns it off (`--enable-features=MacOcclusionForceShutoff`).

## Measured

Linux x86-64, against Electron 45.2.1 (Chromium 156), the latest stable
release (`docs/reports/electron-compare.md`):

| | 0.2.1 (155) | 0.3.0 (157) | Electron 45.2.1 |
|---|---:|---:|---:|
| As published, uncompressed | 179.7 MiB | 182.6 MiB | 273.4 MiB |
| As published, `.tar.xz` | 60.9 MiB | 61.9 MiB | 88.7 MiB |
| Warm start, to first paint | 116 ms | 124 ms | 236 ms |
| Cold start, to first paint | 2279 ms | 2329 ms | 5769 ms |
| Text layout, per layout | 8.1 ms | 7.5 ms | 7.4 ms |
| JavaScript benchmark, all | 1139 ms | 1086 ms | 1161 ms |

On ten real sites, summed medians, zebkit / Electron: CPU while loading
18.3 / 19.8 s, CPU at rest 120 / 131 % of a core, memory 4495 / 4661 MB.

Playwright's own suite at v1.64.1 through `chromium.connect()`: 4047 passed,
148 failed (4046 and 149 on 0.2.1), no test that passed on 0.2.1 failing.
Native automation stays faster than CDP for every operation
(`scripts/automation-bench.sh --check`).

The engine tests pass on Linux, macOS (Apple silicon, macOS 27) and Windows
10 (x64), windowed tests included; each archive, unpacked on its system, runs
`zebkit-js` drawing `examples/ui/todo.mjs` headless and `zebkit-mcp`.

The macOS archive is 5.4 MiB smaller unpacked than 0.2.1's: 0.2.1's framework
carried a stale `content_shell.pak`, Chromium's resources whole, which the
engine never loads (it loads `zebkit.pak`, as on Linux and Windows).
